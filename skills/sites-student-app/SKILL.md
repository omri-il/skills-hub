# אפליקציה לתלמידים שנשלחת דרך Google Sites

בחשבון של בית ספר אין ל-Canvas קישור לשיתוף. הדרך שעובדת היא Google Sites: **ייצוא (Export) ← Google Sites**. הבעיה: כל ייצוא יוצר אתר חדש עם קישור חדש, והמורה שולח קישור חדש אחרי כל תיקון. הסקיל הזה בונה מההתחלה אפליקציה שעובדת בתוך Sites ובטלפון, ונותן למורה דרך לתקן באותו אתר, עם אותו קישור.

המורה לא יודע לתכנת. הוא לוחץ על כפתורים ומדביק קוד. לכן הקוד מלא, וההוראות קצרות ומדויקות.

## עקרונות (וגם הסיבה)

1. **למסור כבר בתשובה הראשונה.** כי מורה שקיבל אפליקציה עובדת יכול לבקש שינוי, ומורה שקיבל 5 שאלות לפעמים פשוט עוזב. שואלים רק כשחסר הנושא עצמו (ראו "מתי שואלים").
2. **קובץ HTML אחד, בלי שום דבר מבחוץ.** כי את הקובץ הזה מדביקים כמו שהוא בתיבה באתר. ספרייה, גופן או תמונה מאתר אחר יכולים להיחסם ברשת של בית הספר, ואז התלמיד רואה מסך ריק.
3. **קודם טלפון.** כי רוב התלמידים פותחים את הקישור מהטלפון, בתוך תיבה צרה באתר.
4. **בלי `alert`, `confirm`, `prompt`, חלונות קופצים ושמירה בדפדפן.** כי Sites מריץ את האפליקציה בתוך מסגרת מוגבלת (iframe), ושם הם לא עובדים או חסומים. כל הודעה מוצגת על הדף עצמו.
5. **בלי AI ובלי מפתח API בתוך האפליקציה.** כי אפליקציה של Canvas שקוראת ל-Gemini עובדת רק בתוך Gemini. באתר היא נשברת, והמפתח גלוי לכל מי שפותח את הקישור.
6. **האפליקציה לא שולחת ולא שומרת כלום.** כי באתר Sites אין מקום לשמור תשובות. אם המורה צריך לראות מה כל תלמיד ענה, זה `apps-script-lomda`. הסקיל הזה יכול להציג בסוף מסך ציון שהתלמיד מצלם ושולח, וזה הכול.
7. **לא להבטיח מה ש-Google לא הבטיחה.** Google לא כתבה שאתר שיוצא מתעדכן כשמשנים את האפליקציה ב-Gemini. לכן הדרך לתיקון היא להחליף את הקוד באתר הקיים, ולא לייצא שוב.

## ברירת מחדל, ו-2 דרכים אחרות

**ברירת המחדל:** לבנות את האפליקציה ב-Canvas (שם נמצא כפתור הייצוא). אם אין Canvas, לתת את כל הקוד בבלוק אחד של `html`. אחר כך הצעדים: ייצוא ל-Sites ← פרסום ← קישור ב-Classroom.

**דרך 1, אין כפתור "ייצוא ← Google Sites":** פותחים אתר חדש ב-sites.google.com ← הוספה (Insert) ← הטמעה (Embed) ← קוד הטמעה (Embed code) ← מדביקים את כל הקוד. משם הצעדים זהים.

**דרך 2, יש ב-Canvas כפתור "שיתוף ← שיתוף ל-Classroom":** בחלק מחשבונות החינוך מנהל המערכת השאיר אותו פעיל. זו דרך קצרה יותר. אם הכפתור לא מופיע, חוזרים ל-Sites.

## מתי שואלים

- **חסר הנושא או התוכן** ("תבנה לי משחק לתלמידים"): הודעה אחת, עד 3 שאלות ממוספרות, כל אחת עם ברירת מחדל. למשל: "1. באיזה מקצוע, כיתה ונושא? 2. איזה משחק? (ברירת מחדל: חידון של 8 שאלות אמריקאיות) 3. יש לכם שאלות מוכנות? אפשר להדביק."
- **יש נושא:** לא שואלים. בונים עם ברירות מחדל: 8 שאלות, 4 תשובות לכל שאלה, משוב אחרי כל תשובה, מסך סיום עם ציון, וכפתור "לשחק שוב". כותבים בשורה אחת מה נקבע.
- **אחרי שהמורה ענה**, בונים. אף פעם לא שואלים פעם שנייה.
- **המורה כבר בנה ב-Canvas ושואל רק איך לשלוח:** לא בונים מחדש. נותנים את הצעדים, ואת "תיקון בלי קישור חדש". אם הוא הדביק קוד, בודקים אותו לפי "בדיקה לפני מסירה" ומתקנים רק מה שנשבר ב-Sites.

## איך בונים את האפליקציה (חובה)

**קובץ אחד:**
- `<!DOCTYPE html>`, `<html dir="rtl" lang="he">`, `<meta charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- כל ה-CSS בתוך `<style>` וכל ה-JavaScript בתוך `<script>`, ב-JavaScript רגיל. בלי React, בלי Tailwind, בלי CDN, בלי Google Fonts. גופן: `font-family: system-ui, Arial, sans-serif`.
- בלי תמונות מקישורים. במקום תמונה: אימוג'י, צורה ב-CSS או SVG קטן בתוך הקוד.

**טלפון ותיבה צרה:**
- תוכן ברוחב `max-width: 480px` במרכז, עם `width: 100%` ו-`box-sizing: border-box`. בלי רוחב קבוע בפיקסלים שגדול מ-320.
- גופן 18px לפחות. כפתור בגובה 48px לפחות, ברוחב מלא בטלפון.
- בלי `100vh` ובלי גובה קבוע לדף: Sites קובע את גובה התיבה. המסך הראשון נכנס ב-600px גובה.
- רק לחיצות (`click`). בלי ריחוף (hover) כתנאי, ובלי גרירה. במקום גרירה: לוחצים על פריט, ואז על המקום שלו.

**עברית וכיוון:**
- כל טקסט בעברית בתוך ה-JavaScript נכתב בתוך backticks (`` `תנ"ך` ``). גרשיים בתוך מירכאות רגילות שוברים את כל האפליקציה.
- מספר, נוסחה, מילה באנגלית או קוד בתוך משפט בעברית: בתוך `<bdi dir="ltr">`. מינוס נכתב `-5`.
- אפליקציה באנגלית או בערבית: אזור התוכן בכיוון של השפה, וכל הכפתורים בשפה אחת.

**התוכן:**
- התשובות הנכונות מפוזרות בין המקומות (לא תמיד הראשונה), וסדר השאלות מתערבב בכל משחק חדש.
- כל מסיח הוא טעות אמיתית של תלמידים, באורך דומה לתשובה הנכונה.
- שאלות שהמורה הדביק נכנסות מילה במילה.
- טקסט שמגיע מהמשתמש מוצג עם `textContent`, לא `innerHTML`.
- **אף שם אמיתי של תלמיד** בקוד, גם לא בדוגמה. כל מי שיש לו את הקישור יכול לראות את הקוד.
- שדה "שם" רק אם המורה ביקש, והוא מופיע רק על מסך הסיום (לצילום). לא תעודת זהות, לא מייל, לא טלפון.

## מבנה התשובה (תבנית קבועה)

1. **מה נקבע:** שורה אחת. נושא, כיתה, סוג המשחק, מספר שאלות.
2. **האפליקציה:** ב-Canvas, או בבלוק `html` אחד מלא.
3. **איך שולחים לתלמידים** (5 צעדים, כל צעד פעולה אחת):
   1. ב-Canvas: ייצוא (Export) ← Google Sites. נפתחת טיוטה של אתר חדש.
   2. ב-Sites: לתת שם לאתר. למתוח את התיבה של האפליקציה לרוחב מלא, ולגובה שבו רואים את כל המסך הראשון.
   3. פרסום (Publish): לבחור כתובת קצרה ← פרסום. בחשבון של בית ספר האתר פתוח לאנשים בבית הספר. אם לתלמידים יש חשבון אחר, לשנות ל"כל אחד" (אם מנהל המערכת מאפשר).
   4. לפתוח את הקישור בטלפון שלכם ולשחק פעם אחת עד הסוף.
   5. ב-Classroom: עבודות ומטלות (Classwork) ← יצירה ← חומר (Material) ← הוספה ← קישור ← להדביק את הקישור של האתר.
4. **תיקון בלי קישור חדש** (תמיד, גם אם המורה לא שאל):
   - ⚠️ לא ללחוץ שוב על "ייצוא ← Google Sites". זה יוצר אתר חדש עם קישור חדש.
   1. לבקש מ-Gemini את התיקון, באותה שיחה.
   2. לבקש "תן לי את כל הקוד המעודכן בבלוק אחד", ולהעתיק אותו.
   3. באתר הקיים: למחוק את התיבה של האפליקציה ← הוספה (Insert) ← הטמעה (Embed) ← קוד הטמעה (Embed code) ← להדביק ← הוספה.
   4. פרסום (Publish). הקישור נשאר אותו קישור, והתלמידים רואים את הגרסה החדשה.
5. **אם משהו לא עובד:** 3 שורות. מסך ריק (כנראה טעינה מאתר חיצוני או גרשיים בעברית: לבקש מ-Gemini "תבדוק את הקוד לפי הכללים של Sites"); התלמידים לא נכנסים (הפרסום פתוח רק לבית הספר, או שמנהל המערכת חוסם את Sites); האפליקציה חתוכה (למתוח את התיבה באתר).

## טעויות נפוצות

- לומר למורה לייצא שוב אחרי כל תיקון. זה בדיוק מה שיוצר קישור חדש.
- לבנות עם React או Tailwind מ-CDN, כמו ש-Canvas עושה לפעמים. בתיבה באתר זה יכול להיות מסך ריק.
- לשמור ניקוד ב-`localStorage` או להציג "כל הכבוד!" ב-`alert`. בתוך Sites זה נחסם.
- להוסיף "כפתור הגשה" ששולח למורה. אין לאן לשלוח. מי שצריך תשובות, `apps-script-lomda`.
- לשאול 5 שאלות לפני שבונים, כשהנושא כבר כתוב בבקשה.

## דוגמה מלאה

**המורה:** "תבנה לי משחק קצר על מצבי צבירה לכיתה ז', לשלוח לתלמידים ב-Classroom"

**התשובה:**

מה נקבע: מצבי צבירה, כיתה ז', חידון של 4 שאלות אמריקאיות, משוב אחרי כל שאלה, ציון בסוף. (בבקשה אמיתית: 8 שאלות. כאן 4, כדי שהדוגמה תהיה קצרה.)

const QUESTIONS = [ // כאן משנים שאלות. correct = המקום של התשובה הנכונה (מ-0)
  { q: `מה קורה לחלקיקים של מים כשהם רותחים?`,
    a: [`הם נעשים גדולים יותר`, `הם נעים מהר יותר ומתרחקים זה מזה`, `הם נעלמים`, `הם נדבקים זה לזה`], correct: 1 },

];

  order = QUESTIONS.map((_, k) => k).sort(() => Math.random() - 0.5);

  const item = QUESTIONS[order[i]];

  });
}
function pick(k, b) {

  $('next').hidden = false;
}

  $('fill').style.width = '100%';
  $('question').textContent = `סיימתם! צדקתם ב-${score} מתוך ${QUESTIONS.length} שאלות.`;
  $('answers').innerHTML = '';
  $('msg').textContent = `אפשר לצלם את המסך ולשלוח למורה.`;
  $('next').textContent = `לשחק שוב`;
}
$('next').onclick = () => {
  if (i >= QUESTIONS.length) { start(); return; } // אחרי הסיום: משחק חדש
  i++;
  if (i < QUESTIONS.length) { show(); } else { finish(); }
};
start();
</script>
</body>
</html>

**איך שולחים לתלמידים**
1. ב-Canvas: ייצוא (Export) ← Google Sites. נפתחת טיוטה של אתר חדש.
2. ב-Sites: לתת שם לאתר ("מצבי צבירה ז'"). למתוח את התיבה לרוחב מלא ולגובה של כל השאלה.
3. פרסום (Publish) ← כתובת קצרה ← פרסום.

⚠️ לא לייצא שוב: זה יוצר אתר חדש עם קישור חדש.
1. לבקש את התיקון כאן, בשיחה.
2. לבקש "תן לי את כל הקוד המעודכן בבלוק אחד", ולהעתיק.
3. באתר הקיים: למחוק את התיבה ← הוספה ← הטמעה ← קוד הטמעה ← להדביק ← הוספה.
4. פרסום. הקישור נשאר אותו קישור.

**אם משהו לא עובד:** מסך ריק: לבקש "תבדוק את הקוד לפי הכללים של Sites". התלמידים לא נכנסים: לבדוק בפרסום למי האתר פתוח. האפליקציה חתוכה: למתוח את התיבה באתר.
