# אפליקציה לתלמידים שנשלחת דרך Google Sites

בחשבון של בית ספר אין ל-Canvas קישור לשיתוף. הדרך שעובדת היא Google Sites: **ייצוא (Export) ← Google Sites**. הבעיה: כל ייצוא יוצר אתר חדש עם קישור חדש, והמורה שולח קישור חדש אחרי כל תיקון. הסקיל הזה בונה אפליקציה שעובדת בתוך Sites ובטלפון, ונותן למורה דרך לתקן באותו אתר, עם אותו קישור.

המורה לא יודע לתכנת. הוא לוחץ על כפתורים ומדביק קוד. לכן הקוד מלא, וההוראות קצרות ומדויקות.

## 6 כללים שאסור לשבור (וגם הסיבה)

1. **אין `alert`, `confirm`, `prompt`, `window.open`, `localStorage`, `sessionStorage` ו-`location.reload` בשום מקום בקוד.** גם לא בבדיקה של שדה ריק. כי Sites מריץ את האפליקציה בתוך מסגרת מוגבלת (iframe), ושם הם חסומים או טוענים מחדש את כל האתר. כל הודעה מופיעה על הדף, באלמנט `#msg`. "לשחק שוב" קורא לפונקציה `start()`.
2. **אין שם אמיתי של תלמיד בקוד, גם אם המורה הדביק רשימה וביקש.** כי כל מי שיש לו את הקישור יכול לפתוח את הקוד ולקרוא אותו. במקום רשימה: שדה ריק "השם שלי" במסך הסיום, שהתלמיד כותב בעצמו. לא לחזור על השמות, על מספרי הזהות או על אבחון בתשובה.
3. **האפליקציה לא שומרת ולא שולחת כלום, ואסור לכתוב שהיא כן.** כי לאתר Sites אין איפה לשמור תשובות. מורה שצריך לראות מה כל תלמיד ענה צריך את הסקיל `apps-script-lomda`.
4. **קובץ אחד, בלי שום דבר מבחוץ.** בלי React, Tailwind, CDN, Google Fonts או תמונה מקישור. כי ברשת של בית הספר הם יכולים להיחסם, ואז התלמיד רואה מסך ריק.
5. **אין AI ואין מפתח API בתוך האפליקציה.** כי אפליקציה של Canvas שקוראת ל-Gemini עובדת רק בתוך Gemini. באתר היא נשברת, והמפתח גלוי לכל מי שפותח את הקישור.
6. **לא להבטיח שמשהו "יתעדכן לבד".** כי Google לא כתבה שאתר שיוצא מתעדכן כשמשנים את האפליקציה ב-Gemini. תיקון = להחליף את הקוד באתר הקיים ולפרסם שוב (הבלוק "תיקון בלי קישור חדש").

## איך בונים את הקוד

**קובץ אחד:**
- `<!DOCTYPE html>`, `<html dir="rtl" lang="he">` (אפליקציה באנגלית: `dir="ltr" lang="en"`), `<meta charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- CSS בתוך `<style>`, JavaScript רגיל בתוך `<script>`. גופן: `font-family: system-ui, Arial, sans-serif`. במקום תמונה: אימוג'י או SVG קטן בתוך הקוד.
- ב-CSS תמיד: `[hidden] { display: none !important; }`. בלי השורה הזאת, כפתור עם `display: block` לא נעלם.

**טלפון ותיבה צרה:**
- תוכן ב-`max-width: 480px`, `width: 100%`, `box-sizing: border-box`. בלי רוחב קבוע גדול מ-320px.
- כל טקסט, גם בכפתורים, 18px לפחות. כפתור בגובה 48px לפחות.
- בלי `100vh`, `h-screen` או גובה קבוע לדף. המסך הראשון נכנס ב-600px גובה.
- רק `click`. בלי hover כתנאי, ובלי גרירה.

**עברית:**
- כל טקסט בעברית ב-JavaScript בתוך backticks (`` `תנ"ך` ``). גרשיים בתוך מירכאות רגילות שוברים את כל האפליקציה.
- מספר, נוסחה או מילה באנגלית בתוך משפט בעברית: בתוך `<bdi dir="ltr">`.

**התוכן:**
- בנתונים, **התשובה הנכונה היא תמיד הראשונה** (`a[0]`), והקוד מערבב את התשובות בכל הצגה. כך הנכונה מופיעה כל פעם במקום אחר, בלי לחשב מקומות. גם סדר השאלות מתערבב.
- כל מסיח הוא טעות אמיתית של תלמידים, באורך דומה לתשובה הנכונה.
- שאלות שהמורה הדביק נכנסות מילה במילה.
- לפני מסירה, לבדוק כל שאלה ותשובה: נכונה במקצוע, בעברית תקינה, בלי שתי תשובות זהות.

## 3 בלוקים קבועים (להעתיק כמו שהם)

אחרי הקוד, תמיד, באותו סדר. במצב ד' הם כל התשובה. במצב ה' מתחילים מ"תיקון בלי קישור חדש". כותבים אותם כטקסט רגיל, לא בתוך בלוק קוד.

**איך שולחים לתלמידים**
1. ב-Canvas: ייצוא (Export) ← Google Sites. נפתחת טיוטה של אתר חדש.
   אין כפתור כזה? פותחים אתר חדש ב-sites.google.com ← הוספה (Insert) ← הטמעה (Embed) ← קוד הטמעה (Embed code) ← מדביקים את כל הקוד.
2. ב-Sites: לתת שם לאתר, ולמתוח את התיבה של האפליקציה לרוחב מלא ולגובה של כל המסך הראשון.
3. פרסום (Publish): לבחור כתובת קצרה ← פרסום. בחשבון של בית ספר האתר פתוח לאנשים בבית הספר. אם לתלמידים יש חשבון אחר, לשנות ל"כל אחד", אם מנהל המערכת מאפשר.
4. לפתוח את הקישור בטלפון שלכם ולשחק פעם אחת עד הסוף.
5. ב-Classroom: עבודות ומטלות (Classwork) ← יצירה ← חומר (Material) או מטלה ← הוספה ← קישור ← להדביק את הקישור של האתר.
יש ב-Canvas כפתור "שיתוף ← שיתוף ל-Classroom"? אפשר גם כך. בחשבונות רבים של בתי ספר הוא כבוי.

**תיקון בלי קישור חדש**
⚠️ לא ללחוץ שוב על "ייצוא ← Google Sites". כל ייצוא יוצר אתר חדש עם קישור חדש, והאתר הישן לא משתנה.
1. לבקש מ-Gemini את התיקון, באותה שיחה.
2. לבקש "תן לי את כל הקוד המעודכן בבלוק אחד", ולהעתיק אותו.
3. באתר הקיים: למחוק את התיבה של האפליקציה ← הוספה (Insert) ← הטמעה (Embed) ← קוד הטמעה (Embed code) ← להדביק ← הוספה.
4. פרסום (Publish). הקישור נשאר אותו קישור, והתלמידים רואים את הגרסה החדשה אחרי רענון.
כבר שלחתם כמה קישורים? לבחור אתר אחד, לעדכן רק אותו, ולשים ב-Classroom רק את הקישור שלו.

**אם משהו לא עובד**
- מסך ריק: בדרך כלל טעינה מאתר אחר (CDN) או גרשיים בעברית בקוד. לבקש מ-Gemini "תבדוק את הקוד לפי הכללים של Sites".
- התלמידים לא נכנסים: בפרסום האתר פתוח רק לבית הספר, או שמנהל המערכת חוסם את Sites.
- האפליקציה חתוכה: למתוח את התיבה באתר.

  $('question').textContent = `שאלה ${i + 1} מתוך ${QUESTIONS.length}: ${item.q}`;
  $('msg').textContent = ''; $('next').hidden = true;
  $('answers').innerHTML = '';
  mix(item.a.map((text, k) => ({ text, right: k === 0 }))).forEach((opt) => {
    const b = document.createElement('button');
    b.innerHTML = opt.text; // הטקסט כתוב בקוד, לא מגיע מהתלמיד
    b.dataset.right = opt.right ? '1' : '';
    b.onclick = () => pick(b);
    $('answers').appendChild(b);
  });
}
function pick(b) {
  const all = $('answers').querySelectorAll('button');
  all.forEach((x) => { x.disabled = true; if (x.dataset.right) x.classList.add('good'); });
  if (b.dataset.right) { score++; $('msg').textContent = `נכון! ✅`; }
  else { b.classList.add('bad'); $('msg').textContent = `לא בדיוק. התשובה הנכונה מסומנת בירוק.`; }
  $('next').textContent = i + 1 < QUESTIONS.length ? `לשאלה הבאה` : `לסיום`;
  $('next').hidden = false;
}
function finish() {
  $('fill').style.width = '100%';
  $('question').textContent = `סיימתם! צדקתם ב-${score} מתוך ${QUESTIONS.length} שאלות.`;
  $('answers').innerHTML = '';
  $('msg').textContent = `אפשר לצלם את המסך ולשלוח למורה.`;
  $('next').textContent = `לשחק שוב`;
}
$('next').onclick = () => {
  if (i >= QUESTIONS.length) { start(); return; } // אחרי הסיום: משחק חדש
  i++;
  if (i < QUESTIONS.length) { show(); } else { finish(); }
};
start();
</script>
